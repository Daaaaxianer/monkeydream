# MonkeyDream 更新与维护

## 写一篇文章

1. 在 `content/posts/` 新建 `.md` 文件，复制 `content/post-template.md` 的格式。
2. 修改顶部 JSON 的标题、摘要、日期、分类、课程编号和证据状态，下面写 Markdown 正文。准备公开时设置 `"draft": false`。
3. 提交到 GitHub 的 `main` 分支，Actions 会自动检查、生成并发布。到仓库 Actions 查看是否出现绿色成功标记。

可以直接在 GitHub 网页编辑或添加文件；也可以在本地修改后提交：

```powershell
git add content/posts assets/uploads
git commit -m "更新博客"
git push origin main
```

仅有文章修改时可以只执行 `git add content/posts`。图片放 `assets/uploads/`，正文引用示例：`![图题](../../../assets/uploads/figure.png)`。修改已发布文章尽量保留 slug，以免旧链接失效。

## 改页面或工具

- 站点介绍、正式网址：`content/site.json`。
- 小工具：`content/tools.json`。
- 页面排版：`assets/css/site.css`；页面内容结构：`scripts/build_site.py`。
- Logo：`assets/logos/`，原图适配规则位于该目录 README。

不要直接编辑 `site/`：下次构建会重新生成。

## 维护习惯

- GitHub Pages 自动托管，没有 Django 服务、数据库或服务器补丁需要维护。
- 域名按时续费；DNS 设置成功后，日常写文章不需要再改解析。
- 更新失败先看 Actions 日志；修复后提交即可。线上保留上一次成功版本。
- 草稿仅隐藏于生成网站，公开仓库中的源文件仍可见。私人笔记、受限数据和旧系统备份不要提交。
- 删除或修改出错，可通过 Git 历史恢复旧文件，再提交发布。

## 域名解析

在 DNSPod 为 `monkeydream.top` 添加以下记录，默认线路，TTL 可用 600 秒：

| 主机记录 | 类型 | 记录值 |
| --- | --- | --- |
| @ | A | 185.199.108.153 |
| @ | A | 185.199.109.153 |
| www | CNAME | daaaaxianer.github.io |

DNSPod 免费版同一主机、同一线路最多两条 A 记录，目前采用上面的三条记录。GitHub 标准配置另包含 `185.199.110.153` 和 `185.199.111.153`；当前不需要为添加这两条而升级套餐。若 @ 或 www 已有指向旧网站的同名冲突记录，替换对应记录；保留邮箱 MX/TXT 等其他记录。
GitHub Pages 已绑定自定义域名 `monkeydream.top`，不需要重复添加。填好解析后等待 DNS 生效，GitHub 会申请证书；在仓库 Settings → Pages 中，证书可用后开启 Enforce HTTPS。DNS 传播和证书准备可能需要一段时间；绑定域名后，GitHub 默认地址也会跳转到该域名。

官方依据：[GitHub Pages 域名设置](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)。
