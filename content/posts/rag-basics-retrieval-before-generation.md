> 本文整理自“学习RAG基础知识”的个人学习对话，覆盖概念入门与检索原理。示例用于教学；尚未搭建论文知识库、运行真实 Embedding 检索或接入大模型 API，不把后续计划写成已完成的成果。

## 1. RAG 为什么要“先查资料”？

RAG 的全称是 **Retrieval-Augmented Generation，检索增强生成**。可以先把它理解为：检索相关资料，再把资料和问题一起交给大模型，让它组织答案。

假设我想问：“实验室去年采用的 RNA-seq 质控要求是什么？”模型即使了解 RNA-seq，也未必见过实验室内部的 SOP。直接回答，可能得到一套通用标准，甚至一段看似合理但没有来源的描述。

RAG 的做法是先找到对应年份的 SOP，再依据其中的内容作答。这里的关键不是让模型凭记忆知道更多，而是**让回答建立在本次检索得到的资料上**。

用“开卷考试”作比喻很直观：模型负责阅读和表达，检索系统负责翻到相关的书页。但能翻书并不保证答案正确，资料、检索和推理都可能出错。

## 2. 一条流程，两个阶段

理解 RAG 时，我先把流程分成建库和回答问题两部分：

```text
建库：文档 → 解析 → 切块 → 生成向量 → 保存文本、向量和来源信息

问答：问题 → 检索 → 选择相关片段 → 组装上下文 → 大模型生成答案
```

采用向量检索时，问题也需要转换成与文档向量兼容的表示，再进行相似度计算。重排序、关键词检索和引用检查可以逐步加入，入门时先理解主流程。

这是一种常见的基础架构；RAG 并不限定必须使用向量数据库，也可以采用关键词检索、混合检索等方式。

## 3. Chunk：把文档变成可检索的片段

一篇论文往往同时包含背景、方法、统计分析和结果。直接把整篇论文表示为一个向量，不容易准确定位某个局部问题；每次都把全文放进模型上下文，也会增加成本和无关信息。

因此，常见做法是将文档拆成 **Chunk（文本块）**。比如查询 SUPPA2 的差异剪接分析流程，通常更需要相关方法段落，而不是整篇文章。

切块时需要权衡：

- **太大**：检索结果混入较多无关内容。
- **太小**：术语解释、限定条件或前后语义容易丢失。
- **适当重叠**：帮助保留跨越边界的信息，但也会带来重复内容和额外计算。

对话中用“每块 100 个词、重叠 20 个词”解释 overlap。这只是帮助理解的示意，不是推荐参数。实际设置要明确使用的是 token、字符还是词，并结合文档结构和检索表现调整。论文中的标题、表格和图注也需要尽量保留语义完整性。

## 4. Embedding：把文本映射到向量空间

**Embedding（嵌入）**是将文本映射成一串数字。合适的嵌入模型会使语义相关的文本在向量空间中更接近，从而支持“意思相近”的检索。

例如，`RNA sequencing analysis` 与 `RNA-seq data processing` 并非完全相同的字符串，但可能具有相近的向量表示。这是语义检索相比纯粹字面匹配的一个优势。

需要记住两个边界：

1. 向量表示是一种模型输出，不是对文本含义的完整、无损编码。
2. 问题和文档必须采用兼容的编码方式；不能随意混用不同模型生成的向量。有些模型还要求分别使用 query 与 document 的编码入口或提示格式。

## 5. 余弦相似度：比较两个向量的方向

余弦相似度是常见的向量比较方式。对于两个非零向量 $A$ 和 $B$：

$$
\operatorname{cos}(A,B)=\frac{A\cdot B}{\lVert A\rVert\lVert B\rVert}
$$

它比较的是两个向量方向的接近程度，取值范围为 $[-1,1]$。同向为 1，正交为 0，反向为 −1。这里的“反向”指向量几何关系，不等于两句话在自然语言中互为反义。

对话中的手算例子是 $A=(1,2)$、$B=(2,3)$：

$$
\operatorname{cos}(A,B)=\frac{8}{\sqrt{5}\sqrt{13}}\approx 0.992278
$$

下面用 Python 标准库复现这个数学例子，无需下载模型：

```python
from math import sqrt

a = (1, 2)
b = (2, 3)

dot = sum(x * y for x, y in zip(a, b))
norm_a = sqrt(sum(x * x for x in a))
norm_b = sqrt(sum(x * x for x in b))
similarity = dot / (norm_a * norm_b)

print(f"{similarity:.6f}")  # 0.992278
```

这个结果只验证了相似度公式，**不代表已经做出了文本语义检索**。向量仍是人为指定的二维数字；真实系统中的向量需要由嵌入模型生成，也要处理零向量等输入边界。

另外，“分数超过 0.8 就相关”不是通用规则。分数分布随模型和任务变化，需要结合实际检索样例评价。

## 6. Top-K：先把相关资料找出来

对话用五段生物信息学资料解释检索：

```python
documents = [
    "RNA-seq can be used to measure gene expression levels.",
    "DESeq2 is commonly used for differential gene expression analysis.",
    "SUPPA2 can analyze alternative splicing events from RNA-seq data.",
    "STAR is a splice-aware aligner for RNA sequencing reads.",
    "Random forests are machine learning models based on decision trees."
]
```

问题是：`Which tool can analyze alternative splicing?`

检索流程是将五段文本和问题编码为向量，计算相似度，再排序取前 $K$ 项。这就是 **Top-K Retrieval**。在这个教学例子中，期望找到包含 SUPPA2 的片段；期望结果并不等于已经获得了模型实测结果。

如果有 $N$ 个文档块、每个向量有 $d$ 个维度，文档向量矩阵的形状通常是 $N\times d$，问题向量是 $d$ 维，逐块比较后得到 $N$ 个分数。这个维度关系比只记住一个框架调用更有助于理解检索。

Top-K 还存在一个限制：它会返回排名靠前的结果，**即使这些结果都不够相关**。因此，“找到了 K 个片段”不能直接视为“找到了答案”。

## 7. 为什么要保存来源，又为什么会需要向量索引？

文档块不应只保存向量，还应保存原文，以及文档名称、版本、页码或章节、获取日期等元数据。这样才能回答：“这句话来自哪份资料？”并支持版本过滤和来源核验。

少量文档可以逐个计算相似度。规模增大后，可以借助向量索引或向量数据库加速搜索，其中一种方法是 **ANN（近似最近邻搜索）**：用一定的近似误差换取更快的检索。

这里也要区分工具类别：**FAISS 是向量相似度搜索与聚类库**，并不等同于一个提供完整数据管理服务的向量数据库。是否需要数据库、哪种索引更合适，要看规模、过滤需求、更新方式和检索延迟。

## 8. 检索之后，才是上下文增强与生成

检索得到的片段会与问题一起组成提示，提供给大模型。例如：

```text
请仅依据提供的资料回答。

资料：
[1] 文档片段及来源
[2] 文档片段及来源

问题：……

回答时标注对应来源；资料不足时明确说明，不要补造内容。
```

这分别对应 RAG 中的 **Augmentation（增强）**与 **Generation（生成）**。提示约束有帮助，但仍需要检查答案是否被资料支持、引用是否与具体论断对应。

尤其在科研学习中，要分清“来源原文报告的结果”和“自己实际运行得到的结果”。RAG 能帮助定位和整理证据，不能代替阅读原文、核验方法或执行分析。

## 9. Embedding、Reranker 与 LLM 分别负责什么？

| 组件 | 主要作用 |
| --- | --- |
| Embedding 模型 | 为问题和文档建立可比较的向量表示，支持初步检索 |
| Reranker（重排序模型） | 对问题与候选片段进行更细致的相关性评分 |
| LLM（大语言模型） | 根据问题和提供的上下文组织答案 |

一种常见的优化方式是：先检索较多候选，再重排序，最后将更少的片段交给模型。对话中的“先取 20 个，再选 5 个”也是流程示意，不是普遍最优设置。

关键词检索与向量检索还可以组合成 **Hybrid Search（混合检索）**。对精准术语、软件名、版本号等查询，保留关键词信号往往值得考虑，再用任务样例验证是否有改进。

## 10. RAG 与微调如何区分？

| 比较点 | 基础 RAG | 微调 |
| --- | --- | --- |
| 主要改变什么 | 当前提供给模型的外部资料和上下文 | 模型参数 |
| 更新资料的典型方式 | 更新文档、索引及元数据 | 准备训练数据并进行训练 |
| 常见目标 | 让回答使用指定资料 | 调整特定任务表现、输出风格或行为 |
| 来源追踪 | 可以保留检索片段和来源，但引用仍需核验 | 参数更新本身不直接提供逐条来源 |

“资料没被模型见过”时，可以先评估 RAG；需要改善任务行为时，再评估微调。二者也能结合。不能笼统断言 RAG 总是更便宜，或微调完全不能学习知识，具体成本与效果取决于任务和规模。

## 11. 怎么判断 RAG 是否有效？

这次学习中最有用的一个区分是：**检索质量和生成质量要分别评价。**

- **检索失败**：知识库中有正确资料，但没有找到，或排名太低。
- **生成失败**：检索片段已包含答案，模型仍误读、遗漏条件或补造内容。

检索端可以关注 Recall@K、MRR、NDCG 等指标；生成端要检查答案是否忠实于上下文、是否正确回答问题、引用是否支持论断。同时记录延迟、费用，以及资料不足时能否合理拒答。

评价最好使用一组有可核验答案和来源的任务样例，而不是只展示一次回答得很好的截图。RAG 能降低部分无依据回答的风险，但不保证消除幻觉。

## 12. 下一步：先实现检索，再逐步扩展

对话提出的 BioRAG 学习路线，可以整理为以下待完成步骤：

1. 用 5–10 段公开生物信息学资料，生成真实 Embedding，手写相似度计算和 Top-K 排序。
2. 加入 PDF 文本解析、切块和来源元数据，检查文档结构是否保留。
3. 根据规模加入 FAISS 等索引，并核对检索质量。
4. 接入大模型，构造基于资料回答的提示，保存可核验的引用。
5. 用固定评价样例，再尝试混合检索、元数据过滤和重排序。

目前这些是学习计划，没有提前宣称代码已运行或系统已建成。先弄清楚每一步的输入、输出和失败方式，再使用框架，后续排查问题会更有方向。
